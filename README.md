# Atomberg IoT MCP server

A local (stdio) [MCP](https://modelcontextprotocol.io) server for the Atomberg public developer API, packaged as a
Claude Code plugin. It lets an AI client read and control the fans and water purifiers on your account.

The server wraps the public API; it does not replace it. It exchanges your refresh token for an access token on its
own, caches it for its 24h life and replaces it before it expires, so the model never sees `get_access_token`.

## Tools

| Tool | API endpoint | Changes anything |
|---|---|---|
| `list_devices` | `GET /get_list_of_devices` | No |
| `get_device_state` | `GET /get_device_state` | No |
| `get_device_analytics` | `GET /get_device_analytics` | No |
| `send_command` | `POST /send_command` | Yes |

`get_lock_dynamic_pin` is deliberately not exposed.

The plugin also adds two slash commands: `/atomberg-iot:home-status` and `/atomberg-iot:purifier-health`.

Every tool call spends one request from the API key's daily quota, plus one roughly every 24h to renew the access
token.

## Install in Claude Code

Requires Node 18 or later on your PATH.

```
/plugin marketplace add <this repository's git URL, or a local path to it>
/plugin install atomberg-iot@atomberg
```

Claude Code then asks for your API key and refresh token, both generated by enabling Developer Mode in the Atomberg
Home app, and keeps them in your system keychain. Change them later with `/plugin configure atomberg-iot@atomberg`.

The VS Code extension does not show that form. There, set the values from a terminal instead; they are stored the
same way:

```sh
claude plugin install atomberg-iot@atomberg --config api_key=<api key> --config refresh_token=<refresh token>
```

Until both are set, Claude Code does not start the server, and none of the tools appear.

## Other MCP clients

Run `plugins/atomberg-iot/dist/index.js` with Node and these environment variables:

| Variable | Required | |
|---|---|---|
| `ATOMBERG_API_KEY` | Yes | From Developer Mode in the Atomberg Home app |
| `ATOMBERG_REFRESH_TOKEN` | Yes | From Developer Mode in the Atomberg Home app |
| `ATOMBERG_API_BASE_URL` | No | Defaults to `https://api.developer.atomberg-iot.com/v1` |

For example, in Claude Desktop's `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "atomberg-iot": {
      "command": "node",
      "args": ["/absolute/path/to/phoenix_mcp_server/plugins/atomberg-iot/dist/index.js"],
      "env": {
        "ATOMBERG_API_KEY": "<api key>",
        "ATOMBERG_REFRESH_TOKEN": "<refresh token>"
      }
    }
  }
}
```

## Layout

```
.claude-plugin/marketplace.json     the marketplace; lists the plugin below
plugins/atomberg-iot/               the plugin, exactly as users receive it
  .claude-plugin/plugin.json        credential prompts and how to start the server
  commands/                         the slash commands
  dist/index.js                     the server, bundled into one file (committed)
src/                                the server's TypeScript source
```

`dist/index.js` is committed because installing a plugin copies it from git and builds nothing. It bundles every
dependency, so the plugin needs no `node_modules`.

## Development

```sh
npm install
npm run build      # type-check, then bundle src/ into plugins/atomberg-iot/dist/index.js
npm run inspect    # call the tools by hand in the MCP Inspector
```

`inspect` reads the variables above from a `.env` file in this folder if there is one; otherwise set them in the
Inspector's UI before connecting.

To try the plugin without installing it, start Claude Code with `claude --plugin-dir ./plugins/atomberg-iot`.
Check the manifests with `claude plugin validate --strict plugins/atomberg-iot` and
`claude plugin validate --strict .`.

To release, run `npm run build`, bump `version` in `plugins/atomberg-iot/.claude-plugin/plugin.json`, and commit the
rebuilt `dist/index.js` with it. Users stay on the version they installed until the version changes.

Nothing but MCP messages may be written to stdout, since that is the protocol channel. Log with `console.error`.
